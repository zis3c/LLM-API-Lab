Architecture & Integration Guide

Fast, Provider-Ready Integration.

Guidelines and developer contracts for testing multi-provider LLM integrations with zero build toolchain friction.

01 Quick Check & Run

The web surface serves as a lightweight static health screen. It does not invoke live third-party endpoints directly from browser sandboxes, preventing CORS leaks.

  • 1 Copy api-keys.env into your local environment process space.
  • 2 Select your desired provider from config/providers.json.
  • 3 Execute your smallest supported model prompt request from your client script or terminal.
Terminal cURL Execution 
curl -X POST https://api.openai.com/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "Hello World"}]
  }'

02 Zero Build Step Architecture

No Webpack, Vite, or Babel compilation step is mandated for runtime health operations. Pure native HTML5, CSS3, and ES modules deliver instant zero-latency loading on any environment.

Validation Script 
# Run self-validation check
npm run check

03 Environment & Secret Isolation

Provider credentials belong exclusively inside process environment variables and must never be hardcoded or committed to version control. Decoy strings provided in demo files are explicitly non-functional for security safety.
